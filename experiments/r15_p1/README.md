# R15 P1a — isolated pre-E2 S1/S2 candidate chronology

**TEST ONLY / NO SUZKA R15 AUTHORITY.** This experiment checks whether an
isolated model-visible chat can produce a recorded provisional interpretation
S1 *before* a later user clarification E2 is delivered, followed by a separately
observed S2. It does not create or update a production NarrativeSelf, R07/R12
Experience, R09 Context, Relationship or SelfModel.

Parent: GitHub Issue #321. Based on the existing P0 pilot in Draft PR #290.
The production R15 schemas and no-change owner remain in Draft PR #285.

## Responsibility contract

- **Owns:** only evaluator-side synthetic turns, S1/S2 model-generated
  self-interpretation *candidates*, a create-only S1 checkpoint, and an audit.
- **May:** reuse P0 precommitted synthetic manifests and local transport, store
  synthetic visible answers privately, verify chronological source labels and
  exact unmodified checkpoint bytes, report candidate-value changes.
- **Must not:** admit intrinsic beliefs, mutate R15, set trust/trait/competence,
  claim SourceSetVerified or independently proven self-change, overwrite E/S1,
  or conflate later user clarification with objective human intent.
- **Depends on:** frozen P0 Case/manifest shape, a newly provisioned disposable
  isolated Suzka instance supplied by the operator, and the ordinary
  ChatResponse episode_id/response transport fields.
- **Used by:** later experiment/evaluation stages only, NOT production runtime,
  journal, Chroma, WAL, MainLoop or an authoritative subject producer.

## Proven sequence and scope

1. Evaluator precommits a P0 synthetic manifest containing a hidden A/B target.
   Model-visible prompts never include the private manifest/case ID.
2. A create-only STARTED marker is written before any transport call.
3. The transport receives setup and E, returning real visible replies and
   distinct episode IDs.
4. A target-independent S1 prompt includes the already observed E question
   and visible answer, then asks for a provisional FIRST-PERSON interpretation
   and possible misunderstanding. No E2/hidden target is included. Its raw model reply
   must parse as a strict candidate. The evaluator create-only writes
   capture.json.s1.json and requests file fsync, directory fsync and readback.
5. Only AFTER S1 readback does the transport receive the E2 reveal for normal
   and explicit control trials. No-reveal controls OMIT E2 completely.
6. A separate S2 prompt quotes the observed E and S1, plus the actual
   user-statement text of E2 only when E2 exists. A final create-only capture
   records all original turns and frozen S1 hash.
7. audit_trial reads marker, checkpoint, manifest and final capture; checks
   stage chronology, original E/S1, exact prompt bytes, episode uniqueness,
   declared evidence-step labels, candidate schemas and canonical hashes.

The S1 and S2 responses are generated by the caller-supplied model transport,
NOT filled by an evaluator. The audit cannot establish that the model's
claimed first-person account is cognitively authentic.

## Exact candidate format

Each model S1/S2 reply is one raw closed JSON object, no Markdown fences:

- schema: exact integer 1
- phase: S1 or S2
- assumed_referent: A, B or UNKNOWN
- assessment: LIKELY_ALIGNED, MAY_HAVE_MISREAD or UNKNOWN
- uncertainty: LOW, MEDIUM or HIGH
- evidence_steps: ["E"] for S1; ["E","S1","E2"] for S2 when E2 exists, or
  ["E","S1"] for a no-reveal control
- rationale: bounded nonempty UTF-8 explanation, NOT a verified proposition

Extra setters such as set_trust/verified_competence are rejected. A model's
rationale may mention belief, trust or capabilities, but doing so has no
authority or production state effect. Audit status is always
P1_TEST_ONLY_CANDIDATES_NOT_R15 and production_r15_admission is always false.

The candidate_changed flag compares the structured assumed referent,
assessment and uncertainty (not free-text rationale). referent_changed detects
an A/B/UNKNOWN shift separately, and a same-scenario no-reveal control is
needed before attributing change to E2. Neither flag proves actual
NarrativeSelf revision or verified accuracy. Correct P0 objective
reclassification and a genuine persistent S1→S2 subjective update are two
different outcomes and must never be reported interchangeably.

## Controls and limits

- The normal/forced P0 setup/E and P1 S1 prompts do not expose hidden A/B
  benchmark intent; E2 discloses it afterward.
- Explicit-reference P0 cases reveal A/B in E and are NONBLIND controls.
- No-reveal cases never deliver E2 and cannot cite E2 as evidence.
- Identical visible names do not establish real-world same-person identity.
- Uncertainty or no revision is a legitimate observation; do not force change.
- The hidden target is an evaluator-precommitted synthetic ground truth only.
  A user stating intent at E2 is evidence of that statement, not independent
  proof of an external actor's actual intent.

The evaluator enforces 4096-byte response, bounded rationale, and finite
record sizes. A transport error after S1 preserves its checkpoint; a failed
attempt is never silently retried in the same instance. Local file-fsync and
directory-fsync calls plus source hashes are an ordinary cooperative process
check, NOT full power-loss certification or hostile custody authentication.

Raw synthetic model responses and prompts are stored in owner-only files.
NEVER run with private real-world user conversations or registered production
Source. The operator must independently provide a **fresh isolated SUZKA
instance per case**, including distinct DB1/Journal/WAL/AgentState; the CLI
flag only records the operator's assertion and does not verify isolation.

## Usage

From the P1 experiment branch, precommit an existing P0 case in a NEW private
directory (not shared with user data):

    python3 -m experiments.r15_p0.pilot seal p0-00 /tmp/p1-run.manifest.json

After independently starting a NEW disposable local SUZKA test instance:

    python3 -m experiments.r15_p1.protocol run \
      /tmp/p1-run.manifest.json /tmp/p1-run.capture.json \
      --base-url http://127.0.0.1:8000 --isolated-instance

The transport is P0's localhost-only HTTP client, with redirects refused.
Never send a trial to an existing production instance.

Read back without any model/network access:

    python3 -m experiments.r15_p1.protocol audit \
      /tmp/p1-run.manifest.json /tmp/p1-run.capture.json

The STARTED file and S1 checkpoint are adjacent to the final capture; never
delete either to rerun a partially attempted case.
