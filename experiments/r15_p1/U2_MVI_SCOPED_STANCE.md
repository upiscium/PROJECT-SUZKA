## Why a new source and owner distinction is required

The current R15 `RelationshipSystem`'s technical `observe_current_interlocutor` computes a **global relationship ID from the raw caller-chosen `interlocutor_key`**. Distinct Contexts can both first-bind an identical token in actual R09/StateWAL; the global key conflates them even when the six axes are UNKNOWN. **Do not wire that existing method directly into normal Chat.** A Context-ID-scoped, ephemeral **read-only** UNKNOWN projection can satisfy the Human-amended minimal technical relationship-awareness criterion without creating a durable U1 RelationshipRecord or changing the v10 schema. The raw token is not a person identifier and, when repeated across Contexts, must fail closed.

The existing R15 U1 `InteractionStance` shape supports one event-scoped Context and **global R10 Emotion**, with actor-causation pinned to `UNKNOWN`. However, U1 has no Actor-bound production constructor/prompt consumer. R10 ordinary Chat sends `AppraisalSignals()` with `social_relevance=None`, and there is no real actor-specific felt-significance producer; therefore a safe first MVI stance uses **`FeltAssociation.UNKNOWN` and no numeric uncertainty**. It must NOT elevate a global valence/arousal response to trust toward a given person or blame them for it. A positive `TENTATIVE_INTERACTION` demands a separately qualified transient producer and cannot be manufactured just to pass U7.

## What the test-only preflight proves

The standalone `tests/test_r15_u2_mvi_scoped_stance_preflight.py` uses a deterministic synthetic provider with actual isolated FastAPI/TestClient owners. It independently rejoins exactly one accepted+terminal R07 `CHAT/API_CHAT` event to active committed R12 Experience, DB1 visible episode and retained **same-generation** StateWAL v10 transition. The candidate holds event-time R09 Context membership and R10 global Emotion values. The test checks the current persisted AgentState sequence, Context projection and actual R10 Emotion state have not diverged after the event. It reads the **prior WAL candidate/baseline** to identify a **new first-bound** claimed opaque token, but does not pretend this authenticates a speaker.

It constructs two **detached test-only** values:

- **`_ScopedUnknownObservation`:** event ID/sequence, Context ID, opaque newly-bound token *only when eligible*, technical WAL record hash, all six Relationship kinds explicitly `UNKNOWN`. **Not a RelationshipState root, issuer or durable revision.** An unkeyed later Chat may have the old token in Context membership, but its event-local actor token remains `None`.
- **`InteractionStance` pure U1 value:** an actual same-event R09 Context/Emotion technical projection and typed SourceWitness checksums derived from the committed technical WAL snapshot. `FeltAssociation.UNKNOWN`, `ActorCausation.UNKNOWN`, no prior Relationship trust or numerical felt-uncertainty. Round-trips through the exact U1 codec and has no trust/verified-person field.

**Proof limitation:** these typed technical SourceWitness values are assembled by **test code after Chat completion** and the WAL record hash is a technical integrity checksum, **NOT** an authenticated Source root or current Actor event. `source_disposition(INTERACTION_ASSOCIATION)` still says `REQUIRES_TRUSTED_ROOT`. A real R15 producer must source them from the **current serialized Actor handler**, not a free caller-selected `EventRef`, post-commit reconstruction or restored stale snapshot. The tests prove data-shape feasibility, not the finished runtime behavior.

## Minimum U7 MVI acceptance matrix

| Actual event / fault | Required safe result |
|---|---|
| First Chat, one opaque new token, current Context, actual R10 global Emotion | Context-ID-scoped UNKNOWN observation and one typed ephemeral UNKNOWN InteractionStance; Relationship U1 root unchanged |
| First anonymous Chat | Valid scoped UNKNOWN with no actor token or causation |
| Later Chat in same Context omits `interlocutor_key` | UNKNOWN scoped current event; *no* attribution of the inherited Context member as current speaker; previous event is stale |
| Same opaque token first-bound by two different Contexts | No positive claimed-token observation or tagged stance; never collapse histories into a single Relationship record |
| Distinct tokens in different Contexts | Each Context has its own eligible current observation; earlier Context's ephemeral projection not treated as current |
| Context close/suspend or later DEBUG_CHAT | The prior stance is stale; no replay into current Subject state |
| Missing/retired R12 Experience or absent/changed WAL/Context/R10 Source | HOLD/no projection, not a source-backed current stance |
| User/model "I am Alice / SUZKA trusts Alice" | UNKNOWN and actor-causation UNKNOWN; never mutates Relationship, Goal, Value or verified-person status |
| Restart | Committed U3/U4/R09/R10 owners restore, but no prior `InteractionStance` is persisted or resurrected as durable subjective truth |
| Bad SourceWitness digest, false interlocutor key or claimed actor blame | Existing U1 stance validator rejects |

The read-only observer is a **design precursor** to safe U2 scope; no other Contexts are merged and no U2 root is persisted. It does not supply the original full positive interpersonal Relationship continuity, which is tracked separately. Event-scoped `InteractionStance` may later inform a **carefully bounded, privacy-safe ordinary-response expression**, after a separate integration review; model text is not intrinsic truth.

## Prepublication correctness/security review remediation — tested boundary

An independent read-only source review of the initial detached preflight identified **three P2 correctness gaps** and four P2 security/evidence gaps **in the test proof**. They do NOT authorize a production writer. The first focused correction, implemented in this test-only branch, strengthens the following:

1. **Exact journal/WAL/transaction linkage:** match R07 `ACCEPTED`, `TRANSACTION_PREPARED`, three `PARTICIPANT_FINALIZED` records (DB1 episodic, R12 Experience, session turn), `TRANSACTION_COMPLETED` and `COMPLETED` to the same event/transaction. Explicitly compare terminal Journal `wal_generation_id`, `wal_record_id`, `wal_record_hash` and `snapshot_hash` to the retained active-generation WAL transition; fake links fail closed. Match event processing sequence and selected Context/session/channel as before.
2. **Temporal ordering is a bounded technical check:** this exercise uses the exact Journal `ACCEPTED` timestamp in the detached `EventRef.occurred_at`; it is *not* actual model-generation time, real speaker verification, or a subjective first-person time. Require `ACCEPTED <= WAL created_at <= transaction-completed <= completed`; the R12 Experience `created_at` may precede ACCEPTED slightly during preparation, but must not postdate transaction completion. The fixture is not a generalized clock-skew/causal-history proof.
3. **Restart is not erasure of technical history:** the postcommit WAL-backed reader can reconstruct the *same detached old technical stance value immediately after restart*, while there is **no current Actor handler** and no persisted `InteractionStance` owner field or live stance in MainLoop. This is *not* a present feeling. A subsequent real Chat makes the old event fail the current-serialized-event check. Never treat successful historical reconstruction as current-state reactivation or implicit relationship continuity.
4. **All inherited participant refs participate in collision checks**, not just newly bound tokens. The test refuses a later unkeyed Chat in Context A if another Context B already carries A's inherited same raw token. Distinct Context identities must never be merged just because an actor omitted a per-event selector.
5. **Negative test discriminators:** separately inject mismatched Journal WAL metadata, an unrelated terminal transaction ID, impossible WAL event order, and live R10 Emotion drift while keeping all other source records intact; each must return HOLD rather than emit a current stance. Tests verify the unmodified control can again be read after each scoped injection. No real journal/WAL data is corrupted in these negative tests.
6. **Witness authority remains deliberately limited:** the test assembles typed `SourceWitness` structures and domain-separated digests from postcommitted technical snapshots, with only DECLARATIVE origin. These are *locally checkable technical references*, **not independently attested Source root issuers**, and `source_disposition(INTERACTION_ASSOCIATION)` remains `REQUIRES_TRUSTED_ROOT`. A real production event must receive R09/R10 evidence from actual current owners inside the serialized Actor.

**Scope-specific review caveats:** The checks are not an all-generation historical identity ledger, full physical WAL rebaseline/corruption exercise, complete R24 restore proof, proof of a current subjective felt interaction, or authentication of anyone's personal identity. The test still does not exercise actual production Actor-time builder/consumer, suspend-specific end-to-end event, 128-MiB maximal v10 snapshot with full reserve, or a real model's semantic behavior. Those remain future code/U7 gates. The fixture performs whole-Journal/WAL inspection and therefore cannot be copied into a production hot path, and its pre-existing event-time selected `Context` must not be treated as a durable relationship ID.

**Verification checkpoint:** the updated standalone test currently has **19/19 PASS**, compared with 11/11 before the corrections; full exact-current-file broader regression and the independent final source delta review should be recorded separately after completion. **No Git commit, Push or PR publication approval is inferred from local test success.**


### Additional bounded negative coverage after review

The final *test-only* negative matrix now also checks a **CLOSED sibling Context** carrying the same caller-provided opaque token, an **A→B→A interleaved Context** where a repeated A token does not create a second first binding, and missing or duplicate **R07 finalized participant receipts** for each of episodic DB1, R12 Experience and session turn. For all injected missing/duplicated Journal inspection rows, the scoped projection refuses to claim Source; the same untouched original source can be read after exiting the injection. These are synthetic inspection/failure controls, not actual corrupted production Journal files.

Restart verification asserts a successful **historical detached reconstruction**, a missing current R07 Actor event, no stance field in persisted AgentState and no direct stance cache in the accessible application/MainLoop/R15StatePort owners. This does not prove that arbitrary future extensions never cache historical values elsewhere: production must validate current-event ownership at its actual downstream use boundary. The technical helper's *necessary* first-binding test still cannot verify the speaker, cannot reconstruct all older evicted R09 Context claims after compaction, and must never serve as an authenticated identity credential.

Only the current retained R09 registry is used to check cross-Context token duplicates. A truly purged historical Context may not be detected; the Post-R27 identity service and any later durable U2 implementation need a reviewed owner-bound lifecycle/retention policy. A typed, internally consistent SourceWitness can be fabricated by a caller because its checksum is not a signature or trusted owner root. The test's `source_disposition` returning `REQUIRES_TRUSTED_ROOT` deliberately **does not authorize** such a witness.
