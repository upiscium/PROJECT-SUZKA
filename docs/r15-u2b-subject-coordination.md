## Rationale and three independent responsibilities

1. **Observed finite expression, actual upstream Sources.** The latest completed ordinary `CHAT/API_CHAT` E must be terminal R07 and its external R12 Experience committed ACTIVE, with a consistent unarchived DB1 response. Existing validated StateWAL transition of E must still be retained in the active generation with exactly the same event UUID/sequence and Context ID/session. Its prior/current Context snapshots must show one **newly bound caller-declared opaque token at that very event**. This does not authenticate the physical speaker or allow attribution of any later Chat where the token was merely a retained Context member.
2. **SUZKA-owned limited assessment rule, not a model verdict.** This experiment is one **closed, explicitly implemented** joint selection Q1: its bounded software protocol requires one shared A/B choice before joint completion. The user's visible E expresses provisional A and Suzka's actual visible reply expresses provisional B (or vice versa), with correctness expressly UNVERIFIED. The separately controlled code-owned rule—not either participant's assertion that "we have a relationship problem"—establishes that the *fixed Q1 task's coordination criterion* is not yet fulfilled. This is only a precisely scoped, programmatic Subject assessment, **not** a real SUZKA R13 Goal/Commitment, independent truth about user intentions, generalized language comprehension, or a stable negative relationship with a verified person. A harmless A/B difference outside the closed joint Q1 protocol is refused.
3. **Durable Subject admission, not Source promotion.** A private `RELATIONSHIP_REVIEW / runtime.relationship_review` event enters the one existing serialized `AgentRuntime` worker. The same `R15StatePort` and `RelationshipSystem` requalify the actual Source and the pre-existing v10 Relationship root. Only if no incompatible prior Relationship exists, the owner adopts one `RelationshipRecord` for the opaque token with `UNRESOLVED_ISSUE` `PRESENT / Inertia.TENTATIVE` about **this particular unfinished joint Q1 interaction**. All other five axes remain `UNKNOWN`, and the claimed/verified person field remains absent. The confidence/estimate are full certainty of the **observed fixed-protocol coordination gap**, NOT a calibrated probability of interpersonal trust, actual other-person intent, objective task correctness, or enduring conflict. The U1 RevisionProof references one actual ACTIVE Experience SourceWitness and the genuine serialized review event; the existing v10/StateWAL internal commit/rollback/recovery owns durability.

These are **distinct**: neither the caller token nor model text may directly set an intrinsic Relationship. No generic owner API receives a caller-authored candidate root, event identity, alternative task, trust score or free-text subjective truth. The internal closed rule is deliberately narrow and should not be extrapolated.

## Bounded eligibility / refusal contract

- Only one latest R07-completed ordinary Chat E and exactly its current committed R12/DB1 match. If a more recent Chat exists, if the earlier WAL transition rotated away, or if any later successful Chat or debug Chat touched E's Context, fail closed rather than projecting older membership/semantics.
- Same task Q1, different bounded provisional A/B choices and explicit Suzka visible `正解は未検証` are necessary but alone not a general unresolved issue: the **separate code-owned Q1 requirement** is necessary too. A/A, Q1/Q2, raw model/user "trust" assertion, unbounded or altered prose, user-provided "this is unresolved", missing Context/token or speaker-attribution claims are not positive.
- The current Context frame must be exactly the same as the event-time WAL snapshot (after **proper conversion** between `ContextFrameSnapshot` and R09 `ContextFrame`), active, in the same session/channel, and have exactly one newly introduced token. A later unkeyed or repeated token turn is not eligible.
- Missing, retired, corrupt, or ambiguous Source owners; V10/Relationship mismatch; wrong private Actor event type/source; an incompatible existing Relationship root; inability to produce exact one-source proof; or a new changed Context frame must result in refusal **before Subject mutation**.
- Repeated qualified review of the same initial Q1 with an already persisted producer-shaped single Relationship root returns no-change rather than another revision. After startup, the existing v10 loader restores exactly the saved root and any new review must reopen actual current Sources. Normal handler failure before WAL restores the prior root; any indeterminate post-WAL failure is fenced by the existing Runtime/Recovery owner.
- A new public API, automatic Chat-triggered Relationship scheduling, broad source history service, R09 identity/alias convergence, arbitrary per-turn person attribution, Action/Decision/Goal mutation, R13-independent authoritative coordination rules, or real-model general semantic accuracy is **not delivered**.

## Research and privacy limitations

- `interlocutor_key` is a caller-supplied **opaque claim**, not an authenticated account or real person. In a durable positive U2 root, `claimed_identity_key=None`. Full speaker/person identity and multi-turn association are deferred to [Post-R27 #346](https://github.com/upiscium/PROJECT-SUZKA/issues/346).
- The only positive initial exercise is a synthetic provider and actual isolated R07/R12/DB1/WAL. It demonstrates **working internal revision and persistence**, not that a general model understands real conversations or independently develops trust. Real-model U7 acceptance remains separate.
- `UNRESOLVED_ISSUE` in this MVI is a narrowly scoped Subject interpretation of an unfinished **cooperative fixed task**, not evidence of a general personal disagreement. This is a *first positive exercise*, not a generic Relationship classifier.
- No raw transcript, hidden thought, model rationale or private profile is persisted in the R15 Relationship root. State stores bounded token references, one Source witness, typed axes, and event-bound proof. Existing AgentState 128 MiB cap and full 16 MiB reserve unchanged. Existing ordinary source reads may have benign physical side effects; the independent Post-R26 full SourceEpoch [#320](https://github.com/upiscium/PROJECT-SUZKA/issues/320) and stronger WAL-generation coherence [#343](https://github.com/upiscium/PROJECT-SUZKA/issues/343) remain deferred.
- `selected_view` is a historical committed owner projection, not a live current-Source attestation. A future consumer in U6/U7/R16 must requalify current Source before claiming any present Relationship meaning. A separate general model/semantic and ephemeral expression mechanism remains unfinished.
